## 5.2. Программные инструменты генерации: `random` и `numpy.random`

Встроенный модуль `random` стандартной библиотеки Python не требует дополнительной установки и предназначен для скалярной генерации единичных псевдослучайных величин и работы с базовыми структурами данных. В модуле `generator.py` функция `run_scalar_demo()` использует вызовы `random.uniform(a, b)` и `random.triangular(a, b, c)` (где аргументы задаются в порядке *минимум, максимум, мода*) для наглядной демонстрации одной реализации проекта со значениями типа Python `float`.

При массовом имитационном моделировании (`N_SIM = 10 000`) скалярная генерация в цикле Python уступает по скорости векторным операциям. Поэтому основная симуляция в функции `run_monte_carlo()` выполняется с помощью `numpy.random`, формирующего сразу целые массивы `np.ndarray` типа `np.float64` на уровне оптимизированного кода C. В основе вычислений лежит современный объектный интерфейс `np.random.default_rng(seed)` на базе генератора `PCG64` (Permuted Congruential Generator). В отличие от устаревшего глобального вызова `np.random.seed()`, изолированный объект `Generator` обладает длинным периодом, высоким качеством потока псевдослучайных чисел и исключает взаимное влияние между независимыми сценариями (`BASE` и `ACCEL`). При этом важно учитывать сигнатуру `rng.triangular(a, c, b, size=n_sim)`, где мода `c` передаётся вторым параметром.

Фиксация начального зерна (`SEED = 42`) совместно со строгим порядком вызовов `RNG_ORDER` обеспечивает полную (бит-в-бит) воспроизводимость вычислительных экспериментов на различных машинах и корректную сопоставимость сценариев.

## 5.3. Метод имитационного моделирования Монте-Карло

Метод Монте-Карло — это численный метод решения задач теории вероятностей путём многократного воспроизведения случайных экспериментов на компьютере. Когда итоговые показатели сложного процесса образуются как сумма нескольких разнородных случайных величин (непрерывных равномерных и треугольных), аналитический вывод точного закона распределения суммы становится громоздким. Имитационное моделирование заменяет аналитическую свёртку распределений серией вычислительных прогонов.

В разработанной модели создания MVP в каждом из $N = 10\,000$ независимых прогонов генерируются реализации восьми независимых непрерывных случайных величин: длительностей $T_{design}, T_{dev}, T_{qa}, T_{mkt}$ и стоимостей $C_{design}, C_{dev}, C_{qa}, C_{mkt}$ согласно параметрам из `config.py`.

Затем для каждого прогона поэлементно вычисляются результирующие величины проекта: общий срок $T_{total} = T_{design} + T_{dev} + T_{qa} + T_{mkt}$ и общая стоимость $C_{total} = C_{design} + C_{dev} + C_{qa} + C_{mkt}$. Полученные массивы из 10 000 возможных исходов сравниваются с ограничениями заказчика (`MAX_DAYS = 60` дней и `MAX_BUDGET = 1200` тыс. руб.). Доля прогонов, в которых произошло нарушение срока ($T_{total} > 60$), превышение бюджета ($C_{total} > 1200$) или одновременное выполнение обоих ограничений, интерпретируется как численная оценка вероятности соответствующих событий ($P_{over\_days}$, $P_{over\_budget}$, $P_{success}$) в вычислительном эксперименте, а при росте числа прогонов средние характеристики закономерно сходятся к теоретическим значениям.
